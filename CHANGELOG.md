# Changelog

## Unreleased

### English
- **Port 3341 → Bitronics SOLO Group** (`pool.bitronics.store:3333`, backup ckpool solo): for Bitaxe/ASICs in a group, with the username `ADDRESS.worker#group` (1% fee; the block is split among the group members by work, only if the group finds it). The proxy passes the `#group` tag to the pool, keeps the worker name clean and the dashboard shows the group next to the pool ("⚡ bitronics group #firstblock"); the Bitaxe worker name also ignores the tag.
- **Second pool for NerdMiners (port 3340 → pool.bitronics.store:3334):** pool.nerdminers.org seems to allow only one connection per home IP: with two NerdMiners they took turns (one dropped exactly when the other connected). Put the second one on port 3340. The two ESP32 pools now back each other up.
- **Unstable pool, quiet events:** a pool that keeps dropping and coming back (pool.nerdminers.org on Nov 8, every minute) now shows one "is unstable" event and one "is stable again", instead of a down/back pair every minute; Telegram only says "back" once the miners have actually returned.
- **pool.nerdminers.org has no backup anymore** (port 3335): no other pool accepts the small ESP32 shares, so sending NerdMiners to public-pool was the same as waiting. Custom `PROXY_ROUTES` can still add one.
- **A pool that is sending work is not "down":** if new connections to a pool fail but the open sessions keep receiving jobs (pool.nerdminers.org refusing new connections when busy), the proxy retries the new connection instead of marking the pool down.
- **NerdMiner on the backup pool:** while a NerdMiner/ESP32 is on the public-pool backup, its shares below the backup's minimum ("Above target") are expected and no longer counted as rejections or alerts (a real block share is still accepted). Its hashrate no longer jumps to absurd values (162 MH/s for a 350 kH/s board) when one share happens to be accepted.
- **SSH stays on after a restart:** if SSH was started outside the dashboard only until the next reboot (`systemctl start`), Settings → 🌐 Network now says "⚠️ Does not start by itself after a restart" and offers **Keep it on after restarts**, which enables the service without touching its configuration (password login, if it was on, stays as it was). Turning SSH on from the dashboard already enabled it at boot.
- **Calmer failback:** when the main pool comes back, the proxy now waits until it has been up for 5 minutes (`PROXY_FAILBACK_STABLE_S`) before moving miners back from the backup, re-testing it meanwhile. A pool that keeps dropping and coming back (like pool.nerdminers.org on Nov 7) no longer kicks the miners each time; the dashboard shows "⏳ … came back, miners return once it is stable".
- **Miner that doesn't come back:** a miner that dropped with a pool switch or a proxy restart and hasn't reconnected in 10 minutes (`PROXY_MISSING_MIN`) shows a warning on the dashboard ("🔌 devkit did not reconnect… Unplug it and plug it back in"), in Recent events and on Telegram, with another message when it reconnects. Some ESP32 firmwares get stuck after the connection drops.
- **New theme ⚡ Material Neon:** bluish graphite with neon green, in Settings → Farm → Visual theme (`THEME=neon`). The theme cards now show two per row.
- Fixed: clicking a theme card in Settings did nothing (a browser-side error introduced with the Neon theme).
- Fixed: the temperature unit field in Settings showed blank when it was never set (it now shows °C, the default).
- **❤️ Support the project:** a discreet item at the end of the dashboard menu opens a dialog with the bitcoin (on-chain) address for donations, a copy button (works over plain http) and "Open in wallet" (`bitcoin:` link). Never shown in kiosk mode; Settings → Farm → "Show 'Support the project'" (`SHOW_DONATE=0`) hides it. The GitHub repository also gets a "Sponsor" button pointing to the donations section.
- Fixed: an empty ping pill showed in the dashboard top bar when there was no ping.
- **PIN in a dialog:** the PIN field left the bottom bar of ⚙️ Settings. Any action that needs it (save, tests, Bitaxe actions, discovery, network, update, backup) opens a dialog asking for the PIN, which is kept only while the page is open; a wrong PIN asks again. The dashboard smart plug buttons use the same dialog.
- **Fixed duplicated records:** the same share reached the dashboard twice, from the pool (2 decimals, e.g. 1,410.95) and from the proxy (more decimals, 1,410.9534), and was recorded twice in the hall of fame (with a second alarm). Now values that match within 0.01% count as one record, keeping the earliest time and the worker name; duplicates already saved are cleaned up when the dashboard starts.
- **Setup without a cable (hotspot):** if the board boots with no network for 90 s and has Wi-Fi with access-point mode (Raspberry Pi built-in, or a USB adapter such as RT5370, MT7610U or AR9271), it creates the open network **HomeMiner-Setup**. On the phone, the "sign in to network" notice opens the wizard, which asks for the home Wi-Fi; the board then joins it (and if the password is wrong, HomeMiner-Setup comes back showing why). If the network drops later, the hotspot comes back and the 🌐 Network tab works from it; with nobody connected it retries the saved Wi-Fi every 10 minutes. New `mineracao-hotspot` service; `HOTSPOT=0` turns it off. Images now ship `dnsmasq-base` and `iw`.
- **Discover miners on the network** (Settings → 🔍 Discover, also in the dashboard menu): scans the home network for Bitaxe and NerdQaxe (AxeOS), ASICs with the cgminer API on port 4028 (Avalon Nano, Antminer…) and ESP32 boards (likely NerdMiner, by the Espressif network card), plus anything already connected to the proxy. Each device says whether it mines through the proxy or directly on a pool, with what to do next; an AxeOS device can be added to the dashboard with one click.
- Fixed in Settings: "Use these" after the Bitaxe scan always named them bitaxe1, bitaxe2… instead of their worker name, and a Sonoff address with a port (`host:8081`) was refused in the browser.

## v0.5.1 — 2026-11-06

### English
- **Power-loss-safe state files:** records, history, achievements, worker list, proxy stats and the Telegram bot state are written atomically (temporary file + fsync + rename) and keep the previous version as `.bak`. If the power drops mid-write (a smart plug, a restart from Telegram), the file is never left cut in half; when reading, a missing or damaged file falls back to the `.bak` and the log says so.
- **Console-style dashboard:** outside kiosk mode the dashboard now has a top bar (active workers or proxy down, pool ping, version, PT | EN, ⚙️ settings) and a side menu grouped into Farm, Mining and Operations, showing one screen at a time. The screen is kept in the address (`#network`, `#luck`…), so it survives a reload and can be bookmarked. Bitaxe gets its own screen, listed only when a Bitaxe is registered, with the count and a warning mark on active alerts. On phones the menu becomes a horizontal strip and the ⚙️ stays visible. Kiosk mode (`?kiosk`) is unchanged; a button on each screen opens it. The content uses the full width and is enlarged on big screens (2K/4K), with chart tooltips still following the mouse.
- Very large records (10 million and up) are shown as "1.8 billion" so they fit the card.

### Português
- **Arquivos de estado à prova de queda de energia:** recordes, histórico, conquistas, lista de workers, estatísticas do proxy e o estado do bot do Telegram são gravados de forma atômica (arquivo temporário + fsync + renomeação) e guardam a versão anterior como `.bak`. Se a energia cair no meio da gravação (tomada inteligente, reinício pelo Telegram), o arquivo nunca fica cortado; na leitura, um arquivo ausente ou danificado volta pelo `.bak`, com aviso no log.
- **Painel com visual de console:** fora do modo quiosque, o painel ganhou barra superior (workers ativos ou proxy fora do ar, ping da pool, versão, PT | EN, ⚙️ configurações) e menu lateral agrupado em Fazenda, Mineração e Operação, com uma tela por vez. A tela fica guardada no endereço (`#network`, `#luck`…), então sobrevive ao recarregar e pode virar favorito. O Bitaxe ganhou tela própria, que só aparece com Bitaxe cadastrado, com a contagem e um aviso quando há alerta ativo. No celular o menu vira uma faixa horizontal e o ⚙️ fica sempre à vista. O modo quiosque (`?kiosk`) continua igual; um botão em cada tela abre esse modo. O conteúdo ocupa a largura toda e é ampliado em telas grandes (2K/4K), com as dicas dos gráficos seguindo o mouse.
- Recordes muito grandes (a partir de 10 milhões) aparecem como "1,8 bilhões", para caber no cartão.

## v0.5.0 — 2026-11-05

### English
- **24-hour charts on the Bitaxe card:** hashrate and chip temperature side by side (each with its own scale), with the min–max range, the current value and a hover/touch readout of time and value.
- **Bitaxe actions:** restart, identify, pause/resume, fan (auto target or fixed) and *point at the proxy* (preview, save, check by reading back, restart) in ⚙️ Settings → Miners behind the PIN, plus Telegram `/reiniciar`, `/pausar`, `/retomar`. A restart asked by the dashboard is not reported as a restart on its own. No overclock, firmware or Wi-Fi changes.
- **°C or °F:** new *Temperature unit* option (`TEMP_UNIT`), also asked in the first-setup wizard (English starts on °F and USD). The dashboard, Telegram, the Bitaxe alert limits (typed, validated and explained in the chosen unit) and the fan target all follow it.
- **Bitaxe alerts:** chip or regulator over the limit, low hashrate for 10 min, on the backup pool, power/hardware fault, not answering, restarted and block found. Telegram announces each one when it starts and when it ends; MQTT gets a `binary_sensor` per alert and per Bitaxe; the dashboard card shows the active ones. Limits in ⚙️ Settings → Miners (`BITAXE_TEMP_MAX`, `BITAXE_VR_MAX`, `BITAXE_HASH_MIN`).
- **Wi-Fi on the Orange Pi and Odroid images:** they now ship NetworkManager handling only the Wi-Fi (the cable keeps the image's own setup), so 🌐 Network → Wi-Fi works with a USB or onboard adapter. The cable shows as connected even when NetworkManager does not manage it.
- **Docker:** new `minerador` profile (`docker compose --profile minerador up -d`) with cpuminer pointed at the proxy, and the 🌐 Network tab now explains how to set up Tailscale, Wi-Fi and SSH on the host instead of disappearing.
- **Pools and ports guide** in ⚙️ Settings → Miners: every proxy port with its pool, backup, live status and ping, who it is for, and how to point a Bitaxe, a NerdMiner or cpuminer (server address and user filled in).
- **Smart plugs:** the "new plug" row is laid out in two lines (four on phones), so the placeholders and options are no longer cut off.
- **⚙️ Settings redesigned as a cloud console:** top bar with the version, side navigation grouped into General, Integrations and System, a page header per section, panels with label and help on the left and the field on the right, and a fixed action bar with the PIN and Save. On phones the navigation becomes a scrolling strip.
- **Bitaxe telemetry (AxeOS API):** register each Bitaxe as `name=IP` (or find them on the network) in ⚙️ Settings → Miners. The dashboard reads hashrate, temperatures, power, J/TH, fan, frequency, pool in use and faults every 30 s (firmware 2.14 and 2.15), shows a Bitaxe card, uses the measured hashrate and power for the worker and the energy cost, and adds one line per Bitaxe to Telegram `/status` plus MQTT sensors. Read-only: no overclock, firmware or Wi-Fi changes.
- **Local miner hashrate** (announced for v0.4.0, but it missed that release) is read with the journal's own timestamps, so it no longer shows 0 H/s when Node and the system disagree on the time zone. **CPU miners with few shares** (target 1) show an approximate hashrate marked with `~` instead of 0 H/s.
- **`health.localMiner`** in `/api/mining` shows how the local miner log is being read (running, hashrate, last line, last read, error).

## v0.4.0 — 2026-11-05

### English
- **Ready-to-flash SD card images** for Raspberry Pi 3/4/5, Orange Pi Zero 3 and Odroid-C2, attached to every release: flash, plug the network cable, open `http://homeminer.local:3000`. Built from the official minimal images (SHA-256 checked), no address, PIN or credentials inside, SSH off on Armbian.
- **Optional local miner:** the images ship cpuminer, and the wizard (and ⚙️ Settings → Miners) asks whether the board should also mine, with how many cores and under which name. The dashboard manages its own `mineracao-minerador` service; a `minerd` service you created yourself is never touched.
- **Update button reports failures** (with the last log lines) instead of spinning.
- **🌐 Network tab** in ⚙️ Settings (PIN): connect to Wi-Fi (NetworkManager) and turn on Tailscale with one tap for access from outside home. The images ship Tailscale installed and off; the authorization link only shows after the PIN. Each section only appears where it works. **SSH** can be turned on there too, key only (password login off).
- **First-setup wizard:** without `BTC_ADDRESS` the dashboard no longer refuses to start: it opens a 4-step wizard in the browser (language, bitcoin address, an admin PIN of your choice, currency and kWh price), saves it, restarts by itself and shows where to point each miner. If `/etc/mineracao.env` already has `SETTINGS_PIN`, the wizard asks for it. `SETUP_WIZARD=0` keeps the old behaviour. This is step 1 of ready-to-flash SD card images.
- **Update button:** ⚙️ Settings → 💾 Backup shows the installed version (and commit), the latest release on GitHub, and an **Update now** button (PIN) that runs `git pull && install.sh` through `systemd-run`. With Docker it shows the `docker compose` command instead.
- **Installer:** can run unattended (no address prompt → wizard; `HOMEMINER_IMAGE=1` skips the PIN so each device gets its own), writes `version.json`, never overwrites a PIN created in the wizard.
- **Ping per pool:** the farm screen and the Telegram `/status` show the ping of each pool in use (e.g. `public-pool 🟢 180 ms · nerdminers 🔴 706 ms`) instead of one average. Backup pools only probed by the failover no longer count, and `/stats` has `totals.pools` with label, ports, sessions, ping and grade. The overall `pingMs` is now averaged only over pools in use.
- **Network tab shows the Tailscale state as soon as it opens** and follows the authorization until it is approved.
- **Weekly backup on Telegram:** new option (⚙️ Settings → Telegram, `TELEGRAM_BACKUP=1`): every Sunday at the summary hour the bot sends the backup file silently. New `/backup` command sends it any time. Off by default, because the file holds saved keys and passwords.
- **Clock on boards without a battery:** the dashboard waits for the clock to sync from the internet (up to `CLOCK_WAIT_MIN`, default 10 min) before collecting, so history, records and the championship never get dates from the image or the last shutdown. A banner shows while it waits, or if it never syncs. `CLOCK_WAIT=0` turns it off.
